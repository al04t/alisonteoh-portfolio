DurHack X · Nov 2025 · Honourable mention · team of 4

How Much Wood Can a Woodchuck Chuck?

An interactive heatmap with a year slider that forecasts woodchuck "wood-chucking" hotspots across Pennsylvania for 500 years, plus a chuck graph and literal log rain. It's built from GBIF sightings, Pennsylvania Game Commission harvest reports, census population density and USDA wood-density data.

With only 2–7 observations per location, time-series models like ARIMA were out. We tried a random forest, then replaced it with an exponential growth projection with stochastic variation, and treated the uncertainty as part of the story.

My role: e.g. data cleaning in Pandas and the Polars projection

Personal project · September 2026

Marketing Research MCP Server

An MCP server that hands Claude a research toolkit: scrape_page returns readable text with navigation and script noise stripped out, extract_meta pulls the title, description, canonical URL and Open Graph tags, analyze_headers maps the H1–H3 hierarchy, and compare_competitors fetches several sites at once with asyncio.gather and returns a comparison table, reporting any site that fails in its own row.

It also ships a prompt that chains those tools into a positioning brief, and a resource holding that brief's template. Written against the MCP Python SDK 2.x, whose API differs from the 1.x examples most tutorials still use.

Personal project · September 2026

Local RAG API

A FastAPI service that stores documents and answers questions from them. A question is embedded with nomic-embed-text, ChromaDB returns the closest chunks, and a local LLM answers using only that context. Every answer comes back with the passages it used, so you can check it.

Documents are chunked by paragraph and tagged with their owner, so a query can be filtered to one person's profile or search them all. Everything runs locally through Ollama: no API keys, and no data leaving the machine.

  • Python
  • FastAPI
  • ChromaDB
  • Ollama

Personal project · Jul 2026

Bayesian Coin Flip Simulator

Bayes' theorem built from the ground up in Python. A hidden coin, either fair or 60% heads, is flipped repeatedly, and the belief in each coin is updated after every flip. Across 200 simulations of 100 flips, the model picked the right coin 83.5% of the time, but reached 95% confidence in fewer than half the runs. Coins that behave similarly need far more evidence to tell apart.

  • Python
  • Probability
  • Monte Carlo
  • Matplotlib
